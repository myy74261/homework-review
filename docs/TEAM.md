# 团队分工

以下为建议分工，姓名、学号和单位由团队补充。

## 成员一：后端与数据负责人

负责内容：

- Spring Boot 工程结构与后端接口。
- 账号、课堂、作业、提交、审核和备课数据模型。
- Spring Security、角色权限与课堂数据隔离。
- 审核版本冲突、历史对比与恢复。
- 数据库结构、演示数据和后端集成。

主要验收：

- 后端测试通过。
- 教师不能访问其他教师课堂。
- 学生不能访问未加入课堂的数据。
- 版本保存和恢复可靠。

## 成员二：教师端与视觉负责人

负责内容：

- 教师端、审核工作台和备课页面。
- 评分量规、问题汇总和最终反馈界面。
- 页面视觉规范、响应式布局和交互状态。
- 自动保存、版本抽屉、备课编辑和导出入口。
- 桌面、平板和手机端界面检查。

主要验收：

- 教师主流程可以连续完成。
- 页面在常见尺寸下无横向溢出。
- 表单、按钮和审核状态清晰。
- 登录页以外的页面视觉统一。

## 成员三：学生端、测试与交付负责人

负责内容：

- 学生注册、课堂码加入、提交与反馈页面。
- 自动化测试、异常场景和权限边界验证。
- 环境变量、依赖清单、启动脚本和运行说明。
- 演示数据、演示流程、截图和比赛展示材料。
- GitHub 提交、版本检查和最终交付。

主要验收：

- 学生可以从加入课堂到查看反馈完成闭环。
- 测试覆盖正常流程和异常权限。
- 新电脑可按照 README 启动。
- 演示过程中不需要临时修改代码。

## 指导教师

负责内容：

- 需求和评价标准把关。
- 教学场景合理性与诚信边界审查。
- 阶段成果评审和风险提示。
- 最终展示内容审核。

## 共同任务

- 每个阶段完成后进行联合验收。
- 关键功能由非开发成员按普通用户流程复测。
- 提交前共同确认 README、演示账号和数据状态。
- 所有成员理解：平台不做自动作弊判定，教师拥有最终判断权。
